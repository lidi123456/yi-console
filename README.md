# Yi Console

用一个界面管理多台机器上的 AI 编程工具会话：Claude Code、Codex CLI、Cursor（cursor-agent）、Kiro（kiro-cli）、Qoder（qodercli）、CodeBuddy（codebuddy），外加普通终端。桌面端支持 Windows / Linux / macOS，手机端支持 Android。

- 每台机器跑一个守护进程 `yi-agentd`，由它启动和托管工具进程。客户端断开、电脑休眠、手机切后台，会话都不会中断，重连后从断点继续接收消息。
- 有两种界面：结构化对话（消息、工具调用、文件 diff、审批卡片）和终端（任何工具都能用 PTY 直接跑）。
- 远程机器有两种连法：直接 SSH（首次连接时自动上传并启动 yi-agentd），或者通过中继服务器（适合手机或另一台电脑连 NAT 后面的电脑）。
- 能导入各工具自己的历史会话并继续聊，支持浏览文件、统计用量和费用，等待审批或回合结束时弹系统通知。
- 对话输入框里：AI 回复中可以接着打字排队，`/` 调出命令和提示词片段，`@` 引用文件，随时切换审批模式。还有命令面板（Ctrl+K）、跨会话搜索消息、按会话查看和提交改动、导出 Markdown。

## 架构

```
 桌面 / 手机 App（Tauri + React）            浏览器（yi-web，调试用）
            │  ClientHub（crates/client）：主机管理、SSH、中继、断线重连
   ┌────────┼──────────────────────┐
   │ 本机   │ SSH exec yi-agentd bridge │ 中继 WebSocket（端到端加密）
   ▼        ▼                        ▼
 yi-agentd（每台机器一个，unix socket / 命名管道，不监听 TCP）
   ├─ claude -p --input-format stream-json …   （结构化）
   ├─ codex app-server                          （结构化）
   ├─ cursor-agent acp / kiro-cli acp           （ACP 协议）
   ├─ qodercli --acp / codebuddy --acp          （ACP 协议）
   └─ PTY                                       （终端模式）
```

| 目录 | 内容 |
|---|---|
| `crates/proto` | 客户端与 yi-agentd 之间的 JSON-RPC 协议类型 |
| `crates/yi-agentd` | 守护进程：会话管理、各工具适配、历史导入、用量统计、开机自启、中继客户端 |
| `crates/link` | 中继协议：身份密钥、配对 / 接入链接、中继层签名鉴权、Noise IK 端到端加密 |
| `crates/relay` | 中继服务器 `yi-relay` |
| `crates/client` | 客户端核心，桌面 / 手机 App 和 yi-web 共用 |
| `crates/web` | `yi-web`：在浏览器里用同一套前端，开发调试用 |
| `app/` | React 前端；`app/src-tauri` 是 Tauri 外壳 |

## 开发

需要 Rust stable、Node 20+。Tauri 在 Linux 上还要装 `libwebkit2gtk-4.1-dev` 等依赖，见 [Tauri 文档](https://v2.tauri.app/start/prerequisites/)。

```bash
# 守护进程、中继、浏览器版
cargo build

# 前端
cd app && npm install && npm run build && cd ..

# 浏览器里调试：http://127.0.0.1:3001/?token=dev
./target/debug/yi-web --listen 127.0.0.1:3001 --dist app/dist --token dev \
  --yi-agentd-dir ./target/debug
```

yi-web 会自动加一台"本机"主机，用 `--yi-agentd-dir` 下的 `yi-agentd`。SSH 主机要自动部署 yi-agentd 时，会在 `--yi-agentd-dir` 或环境变量 `YI_CONSOLE_AGENTD_DIR` 指定的目录里找 `yi-agentd-<os>-<arch>[.exe]`，os 取 linux / macos / windows，arch 取 x86_64 / aarch64。

桌面 App：

```bash
scripts/prepare-sidecar.sh          # 编译本机 yi-agentd，放到 app/src-tauri/binaries/
cd app && npx tauri dev
```

正式安装包、各平台 yi-agentd、Android APK 由 `.github/workflows/build.yml` 构建：推送 `v*` 标签，或者手动触发。Android 的签名密钥放在仓库 secrets 里，`ANDROID_KEYSTORE_B64` 存 base64 编码的 jks，`ANDROID_KEYSTORE_PASSWORD` 存密码，别名必须是 `app`。不配也能构建，但每次构建签名都不同，升级前要先卸载旧版。

## 使用

### 本机

只需要装桌面 App，守护进程不用单独安装：安装包里带了 yi-agentd，App 每次连接本机前会把它同步到 `~/.yi-console/bin/yi-agentd`，守护进程和自启服务都从这里运行。这样升级 App 时，安装目录里的文件不会被守护进程占住。

守护进程由 App 拉起后独立运行，关掉 App 会话也不会停。App 升级后，旧版守护进程会继续运行，"主机管理"里会提示版本不一致；点"重启守护进程"即可换成新版。重启会中断正在进行的回合，会话本身保留，之后发消息会自动接上上下文。

想开机就运行（不用先打开 App），在"主机管理"里点"注册自启服务"，或者手动执行 `~/.yi-console/bin/yi-agentd install`：

- Linux：systemd 用户服务，同时开启 linger；没有 systemd 时退回 crontab `@reboot`。
- macOS：LaunchAgent。
- Windows：写注册表 HKCU Run 项。

### SSH 主机

"主机管理"里添加 SSH 主机，也可以从 `~/.ssh/config` 导入。认证方式支持 ssh-agent、密钥文件、粘贴的私钥和密码，支持跳板机。

第一次连接时会弹出主机指纹让你确认。确认后，客户端检测远程的系统和架构，上传对应的 yi-agentd，再通过 `yi-agentd bridge` 通信。远程机器的 yi-agentd 不监听任何端口。

### 通过中继连电脑（手机或另一台电脑）

电脑在 NAT 后面、手机或另一台电脑直接连不到它时，用中继。下面把被连的电脑称为"目标电脑"。安全设计见 [docs/relay-security-v2.md](docs/relay-security-v2.md)。

1. 在一台有公网地址的服务器上部署 `yi-relay`，见下一节。中继运营者用 `yi-relay invite` 给每台目标电脑生成一条**中继接入链接**（一次性，默认 24 小时有效）。
2. 在目标电脑的桌面 App 里打开「主机」→ 点右上角「让这台电脑可被连接」，按卡片操作：
   - **第 1 步 连接中继服务器**：
     - 粘贴中继接入链接（`yiconsole://relay?...&invite=...`），点「开启」。电脑用链接里的邀请码在中继上登记自己的公钥，之后只靠自己的密钥连接，邀请码随即作废；
     - 这个 App 里已经添加过经中继连接的设备、且中继开启了 `--device-invites` 时，也可以直接点「使用 xxx」：由那台电脑向中继要一个一次性邀请；
     - 没有链接时点「手动填写」，填中继地址、邀请码和证书指纹。
     连不上时卡片上会直接说明原因（没登记、邀请码失效、被中继移除、指纹不对、地址或网络不通）。
   - **第 2 步 在另一台设备上添加这台电脑**：点「生成配对二维码」，得到一个**一次性**的二维码和配对链接，10 分钟内有效，只能配对一台设备。
   - **已配对的设备**：列出配对过的手机和电脑，可以改名，或者单独移除某一台（它会立刻断开，之后要重新配对）。
3. 在要发起连接的设备上，打开「主机」→「配对设备」：
   - 手机：点「扫码」扫目标电脑上的二维码。
   - 另一台电脑：把复制的配对链接发过来。打开「配对设备」时，剪贴板里有配对链接就会自动填上，并显示将要添加的设备名，点「添加并连接」即可。

   添加时这台设备会生成自己的密钥，用配对码和目标电脑完成配对；保存下来的是这台设备自己的凭据，配对链接用完就没用了。添加后目标电脑会出现在主机列表里，标为"经中继连接"，会话、历史、文件、终端都能用。目标电脑要保持 yi-agentd 在运行，想开机就能连，在目标电脑上注册自启服务（见上文"本机"一节）。

没有图形界面的电脑用命令行：
```bash
yi-agentd relay setup 'yiconsole://relay?...'                         # 用接入链接登记并开启
yi-agentd relay setup wss://relay.example.com --invite <邀请码> [--fp <证书指纹>]
yi-agentd relay pair                                                 # 终端里打印一次性配对二维码和链接
yi-agentd relay clients                                              # 已配对的设备
yi-agentd relay revoke <设备 id>                                      # 移除一台
yi-agentd relay reset                                                # 清空所有配对
```

电脑所在网络只能经代理出网时（公司内网常见），yi-agentd 会自动走代理。代理按以下顺序查找：`HTTPS_PROXY`（`wss://` 地址用）或 `HTTP_PROXY`（`ws://` 地址用），然后是 `ALL_PROXY`，Windows 上最后再看系统代理设置。`NO_PROXY` 里列出的主机直连。内网地址（10.x、172.16–31.x、192.168.x 等）也直连。只支持 HTTP 代理。

桌面 / 手机客户端连 SSH 主机和中继时同样默认走代理，规则同上。可以在「系统设置」页的「网络代理」卡片里改成手动指定或不使用代理，设置保存在客户端数据目录的 `client-settings.json`。SSH 经代理建隧道失败时（公司代理常只放行 443 端口）会退回直连。

安全要点：
- 每台电脑、每台客户端都有自己的密钥，私钥只留在自己机器上。中继只知道公钥，看不到内容，也冒充不了任何一方。
- 端到端用 Noise IK 握手（X25519 + ChaCha20-Poly1305），有前向保密：日后密钥泄露，之前录下的流量也解不开。
- 配对二维码里只有电脑的公钥和一次性配对码，用过或过期后泄露也没关系。怀疑某台设备丢失时在「已配对的设备」里移除它；全部作废用「更多 → 重置所有配对」。

### 部署中继

有域名时，建议放在 Caddy 或 Nginx 后面，由它们负责 TLS：

```bash
yi-relay --listen 127.0.0.1:7878 --data /var/lib/yi-relay \
          --public-url wss://relay.example.com --trusted-proxy 127.0.0.1
```

```
relay.example.com {
    reverse_proxy 127.0.0.1:7878
}
```

Nginx：

```nginx
location /v1/ {
    proxy_pass http://127.0.0.1:7878;
    proxy_http_version 1.1;
    proxy_set_header Upgrade $http_upgrade;
    proxy_set_header Connection "upgrade";
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_read_timeout 3600s;
    proxy_send_timeout 3600s;
    proxy_buffering off;
}
```

`--trusted-proxy` 填反向代理的地址（可写多次，支持网段）。只有来自这些地址的连接，中继才读 `X-Forwarded-For` 取真实客户端 IP；不配的话，经代理进来的连接都算成代理的 IP，单 IP 限流和拉黑会误伤所有人。中继地址可以带路径前缀（如 `wss://example.com/hub`），代理把前缀去掉再转给中继即可。

没有域名时，用 `--self-signed`：

```bash
yi-relay --listen 0.0.0.0:7878 --data /var/lib/yi-relay --self-signed --public-url wss://<IP>:7878
```

首次启动会在数据目录生成一张自签名证书，日志里打印它的 SHA-256 指纹。指纹会自动写进邀请链接和配对二维码，客户端连接时只认这张证书。证书文件不删，指纹就不会变。

自签名证书只适合客户端直连中继，或者代理只做四层透传（TCP 转发、不解 TLS）。代理终结 TLS 时客户端看到的是代理的证书，指纹一定对不上：这时代理要配正规证书，中继不用 `--self-signed`。同时配了 `--self-signed` 和 `--trusted-proxy` 的，中继启动时会警告，并且不把指纹写进链接。四层透传拿不到 `X-Forwarded-For`，所有连接都算作代理的 IP，人多时要调大 `--max-per-ip`。

也可以由 yi-relay 自己加载正式证书：`--tls-cert cert.pem --tls-key key.pem`。

管理电脑（在中继服务器上执行，直接读写数据目录，运行中的中继 5 秒内生效）：

```bash
yi-relay invite  --data /var/lib/yi-relay [--ttl 24h] [--uses 1] [--note 备注]   # 生成接入链接
yi-relay invites --data /var/lib/yi-relay [--revoke <邀请 id>]                    # 列出 / 作废邀请
yi-relay devices --data /var/lib/yi-relay                                         # 已登记的电脑
yi-relay revoke  <设备 id> [--cascade] --data /var/lib/yi-relay                   # 移除电脑，在线的立刻断开
```

中继第一次启动、还没有任何电脑时，会自动生成一个 24 小时有效的邀请，打印在启动日志里。

安全相关的设置：

- 准入：电脑必须凭邀请码登记（一次性、会过期，中继只存哈希），之后用自己的 Ed25519 密钥签名证明身份；手机等客户端不需要中继的任何凭据，中继只放行目标电脑授权过的客户端。URL 里不带任何密钥。
- `--device-invites`：允许已登记的电脑代发一次性、10 分钟有效的邀请（App 里的「使用 xxx」一键复用）。默认关闭；多人共用中继时建议保持关闭。代发记录可以在 `yi-relay devices` 里看到，`revoke --cascade` 会连同它邀请的电脑一起移除。
- `--open`：任何人都能直接登记电脑，不需要邀请，只适合公共中继。默认关闭。
- 防止连接耗尽：升级和鉴权各须在 10 秒内完成；默认全局最多 1000 个连接（`--max-conns`），每个 IP 最多 32 个（`--max-per-ip`）；同一 IP 在 10 分钟内出现 10 次可疑失败（签名错、格式错、超时、猜邀请码或配对码），会被拉黑 10 分钟。已被移除的设备自动重连被拒绝不计入，免得同一 NAT 后面的其他设备被误伤。

### 通知

App 开着时，AI 回复完成和等待审批会弹系统通知，通知里带上回复的开头一段。在左下角「系统设置 → 通知」里可以分别开关，也可以选「不在看这个会话时才通知」（默认，窗口最小化、在别的窗口后面、正在看别的会话都算）或「总是通知」，还能发一条测试通知检查系统权限。这些是每台设备自己的设置，存在客户端数据目录的 `client-settings.json`。

手机 App 切到后台后实时连接会断开，这期间收不到通知，回到前台后会话内容会补齐。

### 工具准备

| 工具 | 要求 |
|---|---|
| Claude Code | `claude` 已登录 |
| Codex | `codex` 已登录，需要支持 `app-server` 的版本 |
| Cursor | `cursor-agent` 已登录（执行 `cursor-agent login`） |
| Kiro | `kiro-cli` 已登录 |
| Qoder | `qodercli` 已登录（执行 `qodercli login`）。安装脚本放在 `~/.qoder/bin/qodercli/`，不在 PATH 里也能找到 |
| CodeBuddy | `codebuddy`（npm 包 `@tencent-ai/codebuddy-code`）已登录：运行一次 `codebuddy`，输入 `/login` |

yi-agentd 会读取登录 shell 的 PATH，并检查常见的安装目录。仍然找不到时，在主机设置里填写完整路径，或者设置环境变量 `YI_CONSOLE_PATH` 追加搜索目录。

| 思考等级 | ✓（立即生效） | ✓（下一回合生效） | — | — | — | — |
| 图片输入（单张 ≤ 5MB，png/jpeg/gif/webp） | ✓ | ✓ | ✓ | 看工具是否声明支持 | ✓ | ✓ |

### 会话状态栏

会话输入框下面有一行状态栏，在「主机设置 → 会话状态栏」里配置，只对这台主机上的会话生效：

- **内置字段**：模型、上下文、token、费用、上一轮耗时、Git 分支（含改动数和领先/落后）、目录、状态、工具、账号额度，勾选并调整顺序；
  也可以写一个模板，例如 `{model} · {branch}{dirty} · {context}`。
- **自定义命令**：和 Claude Code 的 `statusLine` 约定一样，在会话目录里执行，stdin 收到一段 JSON（`session_id`、`cwd`、`model`、`workspace`、`cost`、`context_window`，
  另有 `yi_console` 里的工具、用量、git 信息），输出的第一行显示出来，支持 ANSI 颜色，3 秒超时。Windows 上用 cmd 执行。
- 没填命令时，Claude Code 会话默认沿用 `~/.claude/settings.json` 里配置的 `statusLine`，Windows 上用 Git Bash 执行。项目里的 `.claude/settings*.json` 只在这个目录（或上级目录）已经在 Claude Code 里点过「信任」时才用，免得打开别人的仓库就执行里面的命令。

### 对话输入框

- **排队发送**：AI 还在回复时可以继续打字，按 Enter 后消息进入队列，显示在输入框上方，这一轮结束后按顺序自动发出。点「立即发送」会中断当前回合、马上发这条；点 × 或在空输入框里按 ↑ 可以撤回到输入框改。手动中断（Esc 或停止按钮）后队列不会自动发出。队列存在 yi-agentd 里，手机和电脑看到的是同一份，守护进程重启后清空。
- **`/` 命令**：在输入框开头打 `/`，会列出：
  - 提示词片段：在「主机设置 → 提示词片段」里维护，存在这台机器的 yi-agentd 上；
  - Yi Console 自带的操作：切换模型、切换审批模式、查看改动、导出、重命名、在同一目录新开会话等；
  - 工具自己的命令：比如 Claude Code 的 `/compact`、自定义命令，Cursor / Kiro 通过 ACP 报告的命令。
- **`@` 文件**：打 `@` 加文件名的一部分，在会话目录里模糊查找（git 仓库按 `git ls-files`，遵守 `.gitignore`），选中后插入相对路径。
- **模型和思考等级**：输入框右下角切换，下一条消息生效，也可以打 `/model`。菜单底部可以选思考等级（Claude Code、Codex 支持，可选等级按模型报告的来），新建会话时也能选。
- **引用文件**：文件面板里右键「复制」（或在文件树里点一下再按 Ctrl+C），到输入框里粘贴，插入 `@相对路径`，和拖进来一样。系统里复制的文件（资源管理器里 Ctrl+C）粘贴或拖进输入框时，图片照常作为图片发送，其他文件传到主机上这个会话的上传目录（`~/.yi-console/uploads/<会话 id>/files/`，单个不超过 50MB，删除会话时一起删），插入 `@绝对路径`。SSH / 中继主机也可以。
- **图片**：粘贴或拖进输入框，双击缩略图放大；对话里的图片点一下放大，滚轮缩放、拖动查看、可以旋转，Esc 关闭。
- **审批模式**：输入框左下角可以随时切换「默认 / 自动接受编辑 / 只读规划 / 全部放行」，也可以按 Shift+Tab 轮换。设置记在会话上，恢复会话时沿用。Claude Code 切到「全部放行」要重启工具进程，正在回复时会等这一轮结束后自动重启；以 root 运行时 Claude 不允许全部放行。

### 窗口和右键菜单

- 界面主题在左下角「系统设置 → 外观」里选：跟随系统 / 亮色 / 暗色，每台设备自己记。
- 侧边栏可以拖右边缘调宽（默认就是最窄的 244px，最宽 480px），双击边缘还原，每台设备自己记。
- 桌面版去掉了系统标题栏，顶部一行和侧边栏同色：左边是收起侧边栏、后退、前进，右边是最小化 / 最大化 / 关闭（macOS 保留系统的红绿灯）。空白处可以拖动窗口，双击最大化。
- 右键菜单都是自己画的，不再出现 WebView 默认的那套：会话上右键可以打开、重命名、置顶、查看改动、导出、复制路径、停止、删除；输入框里右键是剪切 / 复制 / 粘贴 / 全选；选中文字后右键可以复制。
- 重命名、删除确认等也换成了应用内的弹窗。
- AI 正在输出时可以直接选中复制，选中期间这段回复暂停刷新，松开或取消选中后补上。
- 发送消息后自动回到底部；往上翻得比较远时右下角会出现「回到底部」按钮（回复进行中带一个蓝点）。

### 终端会话

- 外观参照 Windows Terminal：Cascadia Mono 字体（中文回退到雅黑 / 苹方），One Half Dark / One Half Light 配色，GPU 渲染，中文按两格宽对齐。「系统设置 → 终端外观」里选跟随界面 / 暗色 / 亮色和字号，终端下方状态栏右侧也能随时切换。
- 右键：复制、粘贴、全选、清屏；有选中时 Ctrl+C 复制，Ctrl+V 粘贴，Ctrl+Shift+C / V 也可以。
- **tmux 保持**：Linux / macOS 上装了 tmux 3.2 以上时，终端会话放在 tmux 里运行（单独的 socket `tmux -L yi-console`，不影响自己的 tmux），守护进程重启、升级后程序不中断，yi-agentd 启动时自动接上。tmux 不显示状态栏、不接管鼠标，滚动和选中仍由 Yi Console 的终端处理。在「主机设置 → 会话进程」里可以关闭。删除会话或「停止进程」会连 tmux 里的程序一起结束。
- **对话 / 终端一键切换**：会话页右上角的「终端模式」/「对话模式」按钮（会话右键菜单里也有）把同一个会话在两种界面之间切换，工具接着原来的会话，上下文不丢。切到终端时用工具自己的交互界面 resume；切回对话时，终端里聊的内容会导入对话记录。切换会结束当前的工具进程，正在进行的回合会中断。
- **闲置释放**：对话模式的会话闲置超过 30 分钟（可在「主机设置 → 会话进程」里改，或关掉）会结束背后的工具进程省内存，聊天记录都在，下次发消息自动接着原来的会话继续。

### 搜索、改动和导出

- **工作区文件**：会话页右上角的文件夹按钮打开右侧文件面板。没打开文件时只有一栏文件树；点开文件后变宽，上方是打开过的文件标签（放不下时可以用滚轮横向滚动，当前文件总会滚到可见处，右边的下拉列出全部打开的文件；标签右键可以关闭其他、关闭左侧、关闭右侧）。面板右上角可以全屏，左边留一窄条对话区，点它退出全屏。打开过哪些文件按工作目录记住，下次打开面板（或重启 App）时恢复这些标签和当时在看的文件。文件树用颜色和字母标出 git 改动（M 修改、U 新文件、D 删除），git 状态在回合结束、窗口重新获得焦点时和每 10 秒刷新一次（终端里提交后也能及时更新）。切到「改动」只看改过的文件，打开后可以在「文件 / 改动」之间切换看 diff。
  - **查找**：侧栏「搜索」在文件内容里搜（可区分大小写、全词匹配，git 仓库遵守 .gitignore），点结果跳到那一行；Ctrl+P 按文件名快速打开，输入 `@` 列出当前文件的函数、类、标题（Ctrl+Shift+O），输入 `:` 跳到某一行（Ctrl+G）。
  - **拖拽**：文件树或标签里的文件拖进输入框，插入 `@相对路径`；系统里的文件拖进文件树，上传到那个目录（单个不超过 50MB，SSH / 中继主机也可以）。
  - **下载 / 系统打开**：右键「下载」把文件存到本机；本机主机上还可以「用系统默认程序打开」「在文件管理器中显示」。
  - **并排和比较**：右键「在右侧打开」把另一个文件放在右边只读对照，「与当前文件比较」看两个文件的差异；diff 可以在左右并排和上下之间切换。
  - **图片**：底部工具栏可以缩小 / 放大、适应窗口和原始大小切换、左右旋转、水平翻转、全屏查看；滚轮按鼠标位置缩放，拖动平移，双击放大或还原，手机上双指缩放。快捷键 `+` `-` 缩放，`0` 适应窗口，`1` 原始大小，`R` / `Shift+R` 旋转。
  - **预览**：PDF（用系统 WebView 自带的阅读器），CSV / TSV 显示成表格，可以筛选行。
  - **浏览器标签**：标签栏右边的地球按钮（或「新建」菜单里的「打开网页…」）新开一个浏览器标签，输入地址或端口号，新标签页上会列出主机上正在监听的端口，点一下打开。远程主机上的 `localhost` 指那台机器，会自动做端口转发再打开。HTML 文件右键「在浏览器标签中打开」，或者打开后切到「预览」，页面里相对路径的 css、js、图片都从主机上读，保存后自动刷新。网页放在 iframe 里：不允许被嵌入的网站（很多外部网站）会是空白，点「用系统浏览器打开」；页面里点链接跳转后地址栏不跟着变。
  - **Markdown**：默认打开预览，可以切到「源码」或「分栏」（左边编辑、右边实时预览，两边滚动对齐），记住上次的选择。预览里的相对路径图片从主机上读取，点相对链接在面板里打开那个文件，`#标题` 链接跳到对应标题；Ctrl+Shift+O 的大纲在预览里也能用。
- **回复显示风格**：会话页右上角的列表按钮在「简约」（思考和工具调用收成一组）和「Claude Code」时间线之间切换，系统设置「对话外观」里也能改。
- **会话用量**：会话页右上角的用量按钮（显示本会话 token 和费用，「更多」菜单里也有「查看用量」）打开弹窗，列出这个会话的输入、输出、缓存 token、费用、上下文占用，以及这个工具账号的额度（同用量统计页），可以刷新。
- **搜索**：侧边栏顶部的搜索框边打字边按会话标题和目录筛选；按回车（或点下面的「在消息里搜索」）在所有已连接主机的会话里搜用户消息和回复，点结果直接跳到那条消息。也可以按 Ctrl+Shift+F。
- **主机菜单**：侧边栏里每台主机行的「…」或右键菜单里有历史会话、浏览文件、打开终端、用量统计、主机设置；底部「添加 / 管理主机」进主机管理。
- **会话列表**：会话按目录分组，点目录名可以折叠（折叠后显示会话数，有会话在运行或等待审批会亮点）；会话可以置顶（悬停时点图钉，或右键）；超过 3 天没动、已经退出的会话收进「更早的 N 个会话」。
- **查看改动**：会话菜单 →「查看改动」（或输入框里 `/changes`）打开右侧文件面板的「改动」视图。会话里有工具改过文件时默认只列这些（可以取消「只看这个会话改的」），点开看 diff。会话目录不是 git 仓库时，只列出工具调用里记录的修改，点开看 diff。
- **导出**：会话菜单里可以复制为 Markdown 或下载 `.md` 文件，包含用户消息、回复和工具调用摘要，不含思考过程和工具输出。

### 端口转发

远程主机上跑的开发服务器、接口，可以转发到本机浏览器里打开。入口在侧边栏主机行的「…」菜单、会话菜单、命令面板里的「端口转发」。

- 页面下方列出主机上正在监听的 TCP 端口和对应进程，点「转发」或「转发并打开」；也可以手动填端口号。
- 本机端口默认和主机端口同号（比如 3000 转到 localhost:3000），被占用时自动换一个，也可以自己指定。
- SSH 主机走 SSH 自带的端口转发（sshd 禁止 TCP 转发时，自动改走 yi-agentd）；中继主机和经电脑转发的主机，每条连接新开一条中继通道，由主机上的 yi-agentd 去连它自己的端口。yi-agentd 仍然不监听任何网络端口。
- 只能转发到主机自己的 127.0.0.1，本机这边也只监听 127.0.0.1。转发在关闭 App 后结束。
- 本机主机不用转发，页面上直接「打开」。
