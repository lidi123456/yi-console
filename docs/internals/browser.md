# AI browser (`yi_browser`)

The design and its reasons are in [docs/proposals/browser.md](../proposals/browser.md); it follows vercel-labs/agent-browser (Apache-2.0) where not stated otherwise. This file describes what is built (P1a and P1b).

## Pieces

- `crates/browser` (package `yi-browser`): a CDP engine with no yi dependencies.
  - `launch.rs` finds the browser. The order is the explicit path, then Chrome, then Edge on Windows; Chrome / Chromium / Edge on macOS and Linux; then the Puppeteer / Playwright caches. It starts the browser with agent-browser's arguments (`--remote-debugging-port=0`, `--headless=new`, own `--user-data-dir`, `--no-sandbox` as root or in containers) and reads `DevToolsActivePort`, deleting a stale one first. Chrome's stderr is drained, and its last lines go into start errors.
  - `cdp.rs` is one browser-level WebSocket with flattened sessions.
  - `browser.rs` keeps the state: tabs (from `Target.targetCreated`; tabs a page opens are reported to the model as a note), out-of-process iframes (`Target.setAutoAttach {flatten}` per tab), lifecycle events, dialogs, console (200 lines per tab) and refs.
  - `snapshot.rs` builds the accessibility snapshot: agent-browser's role lists, one level of inline iframes, and DOM hints for unnamed or duplicate controls.
  - `actions.rs` holds the actions. Before a click, a page script checks the element (hidden, disabled, outside the viewport, covered by what), and the click point is shifted by the frame offsets.
  - `keys.rs` sends key events.
  - `tools.rs` has the MCP schemas, the action categories and `Browser::call` / `call_with` (upload roots). It marks the browser busy during a call, and adds a note when a person used the live view since the last call.
  - `view.rs` is the live view: `Page.startScreencast` (JPEG) on the current tab while `set_screencast(Some)`, restarted when the tab changes; every frame is acked to Chrome at once and only the latest is kept (`frames()` watch). `view_state()` gives URL, title, tabs, dialog, selected frame and busy tool. `human_input` sends a person's mouse / key / committed text (`Input.insertText`) / touch / dialog answers without the tool lock.
  - `net.rs`: request log (500 per tab), routes, the domain allowlist and downloads. `Fetch.enable` is set per tab, iframe and (with an allowlist) dedicated worker session: the browser target's own `Fetch` does not see page requests. The allowlist also installs agent-browser's init script (WebSocket / EventSource constructors, `sendBeacon`, `RTCPeerConnection` removed, `navigator.serviceWorker` hidden, Worker / SharedWorker started through a guarded blob) and `--force-webrtc-ip-handling-policy=disable_non_proxied_udp`; iframes and workers are attached paused so the guard is in first. Downloads use `Browser.setDownloadBehavior allowAndName` into `<data>/browser/downloads/<sid>/`, then are renamed to the suggested file name.
  - `extra.rs`: `browser_frame` (selected frame per tab; reads, snapshots and eval go to its default execution context), `browser_diff` (LCS line diff against the tab's previous snapshot), `browser_upload`, `browser_set` (viewport, `prefers-color-scheme`, offline; reapplied to new tabs), `browser_eval`.
  - `launch.rs` also starts a private Xvfb (`-displayfd`) for a headed browser on Linux without `DISPLAY` / `WAYLAND_DISPLAY`.
- `crates/yi-agentd/src/browser/mod.rs` is the gateway: `Browsers`, one `Grant` + `Slot` (lazy Chrome) per session. The slot also holds the live-view state: frames renumbered per slot (`seq` never goes back across restarts), a tick channel for status changes, the viewers and their size / quality (one screencast at the largest asked for), headless or headed, and a note for the AI's next result.
- Live view protocol (`serve_conn`, per connection, never through `Hub::emit`): `browser.view.attach {sessionId, maxFps?, maxWidth?, quality?}` returns the limits in force and starts `browser.status` (deduplicated) and `browser.frame {sessionId, seq, data, metadata}` notifications. One frame is in flight until `browser.view.ack {seq}` (or 2 s), at most `maxFps`; a newer frame replaces an unsent one. Defaults: local 30 fps / 1280 px / q70, SSH and relay 2 fps / 640 px / q40. `browser.view.detach` or closing the connection drops the view. `browser.view.input {sessionId, events}` is in the normal dispatch.
- `session.browserUse` actions beyond enable / stop / pause / resume: `start` (launch now, e.g. to sign in), `open {url}` / `back` / `forward` / `reload` / `tab {tab}` (a person's navigation; goes through the tool lock so it waits for the AI's current step, and the AI is told), `headed` / `headless` (restart with the same profile, reopening the http(s) tabs and reselecting the current one; refs are gone and the AI is told; a timeline note is emitted).
- Hub: `browser_use()` / `browser_status()` and the `+browser` launch fingerprint. `revoke_desktop` (kill / delete / clear / mode switch) also stops the browser. Interrupting pauses it, and the next message resumes it.
- Frontend, live view: `AiBrowser.tsx`, the file panel tab `aiweb:<sid>` (counted by `isWebTab`, so file operations leave it alone; restored only for its own session). It attaches while the tab is on screen and the window visible, draws frames on a canvas sized to the panel at the page's aspect ratio, and acks after drawing. Pointer positions map to viewport CSS pixels through the frame metadata. A hidden textarea takes keys (printable keys go with their text, Enter as `\r`), IME (`compositionend` → `text`) and pastes; input is queued, one batch in flight. Touch: drag scrolls, tap clicks. Like Claude in Chrome, while the AI acts (and 1.5 s after each step) the picture gets a glowing orange frame and a bottom pill "AI is using this page · Stop" (Stop is `session.interrupt`, which also pauses the browser), and the tab icon pulses. Frames carry no cursor, so the engine records where its own mouse events went (`ViewState.pointer`, with a press counter) and the view draws an orange pointer that glides there, with a ring on each click. Bars: back / forward / reload, an editable address (opens in the AI browser), tabs menu, quality presets, pause / resume, real window ↔ panel (local host with a display), a status line (AI acting / paused / idle / frame) and a dialog card. `SessionView` opens the tab by itself on the first `browser_use` running event of a session (desktop only, once per window), widening the panel; `FilePanel` hides the tree for it. The `web:` tab has "Hand to AI browser" (enable if needed, then `open`). Host settings have an "AI browser" card (`SettingsView`).
- Frontend, chat: `browserUse.ts` (any non-Android host, structured mode, the 7 AI tools), `BrowserUsePanel.tsx` (on/off dialog next to `ComputerUsePanel`), and `ChatView` folding (`browser_use` events go into the AI tool's own call row, the same as `computer_use`, matched by `yi_browser` + tool name; for CodeBuddy's `DeferExecuteTool` rows the wrapped `toolName` in the input counts too).

## From agent-browser, round two (2026-11-18, compared at f85ed4d)

- Robustness: `cdp.rs` replaces lone UTF-16 surrogate escapes before parsing (a page title or console line with one used to drop the whole message and leave its command waiting 30 s), fails a command whose message still doesn't parse by its `"id"`, removes timed-out commands, and fails the commands of a session on `Target.detachedFromTarget` (later sends to it fail at once). The gateway's `ensure` uses `Browser::healthy` (process not exited and `Browser.getVersion` within 5 s) instead of only the socket state. Launch adds `--disable-renderer-backgrounding`, `--disable-background-timer-throttling`, the crash-bubble switches and `--allow-insecure-localhost`; each tab gets `Emulation.setFocusEmulationEnabled` and `Inspector.enable` (a crash marks the tab, the next call says to reload). Linux lookup also tries fixed paths (`/opt/google/chrome/chrome`, `/snap/bin/chromium`, ...).
- Tabs: when the AI's current tab is closed by the page or a person, the live view moves to another tab but the AI's next call fails with `tab_gone` text listing the others, until it selects one (agent-browser `tab_binding.rs`). `browser_tabs select` probes the tab (3 s) and reloads one that doesn't answer, saying so.
- Navigation results add the main document's HTTP status when >= 400 and the number of console errors since the load; navigation errors get hints (`ERR_CONNECTION_REFUSED` on localhost: the dev server isn't running; certificates; unsafe ports; HTTP auth; allowlist). Host setting `ignoreHttpsErrors` adds `--ignore-certificate-errors`.
- Waits: `state` visible / hidden / attached / detached for text and elements, `fn` (a polled JS condition, category `eval`), timeout messages that name the condition and the URL.
- Clicks: `SETTLE_JS` waits until the element's box is stable over two animation frames (up to 5 rounds) and centers one still off screen; the covered check accepts a hit on an ancestor of the target. `kind` adds `middleclick` and `focus`, `modifiers` (Alt / Control / Meta / Shift). `browser_drag` does mouse down, ten moves, up; with `Input.setInterceptDrags` an HTML5 drag is finished with `Input.dispatchDragEvent`.
- Elements: every element argument takes `ref` or `selector` (CSS, or `xpath=`; the first visible match, the count is reported). `browser_find` gives refs by role + name (from the AX tree), text, label, placeholder, alt, title, test id or CSS. `browser_get` adds `attr`, `box`, `styles`, `count`. `browser_scroll` with a ref and a direction scrolls inside the nearest scrolling container. `browser_select` on a non-`<select>` opens the combobox, waits for `role=option` (portals included) and clicks matches; labels compare with NBSP as a space.
- Snapshot: `CURSOR_JS` finds elements with no interactive role that act as controls (cursor:pointer not inherited from the parent, `onclick`, `tabindex`, `contenteditable`) and visible labels of hidden radios / checkboxes; they get refs as `clickable` / `focusable` / `editable` / `radio` / `checkbox` (agent-browser `find_cursor_interactive_elements`, `promote_hidden_inputs`). Nothing is written to the DOM: the elements come back by reference and are released with their object group. Adjacent text pieces at one depth are merged (no space around CJK). `ref` limits a snapshot to one subtree. `browser_diff` compares only snapshots taken with the same options.
- Network: the log keeps request / response headers, post data, MIME, size and the session; `requests` shows `#id` and filters by method and status (`404`, `4xx`, `>=400`); `detail` shows one request with `Authorization`, `Cookie`, `Set-Cookie` and similar values replaced by their length, and the body through `Network.getResponseBody` (20,000 characters). Redirect hops stay separate entries. Routes take `headers` and `resourceType`, send JSON text as `application/json`, answer CORS preflights (`OPTIONS` with `Access-Control-Request-Method`) and echo the request's `Origin` with credentials. With an allowlist, a blocked top-level document gets a short "blocked" page instead of Chrome's error page, and the model hears about every blocked navigation. Downloads are claimed once each (two finishing close together go to two calls; `browser_download` only takes one that started after its click); a canceled one says so.
- New tools: `browser_cookies` (get for the page or `all`, httpOnly included; set / delete / clear, category `storage`), `browser_storage` (local / session get / set / remove / clear), `browser_find`, `browser_drag`. `browser_set` adds `device` presets (viewport, scale, `mobile`, touch, user agent), `scale`, `mobile`, `userAgent`, `reducedMotion`, `throttle` (slow3g / fast3g / 4g), `locale`, `timezone`, `geolocation` (also grants it), `permissions`, `headers` (all requests via `Network.setExtraHTTPHeaders`, or with `headersOrigin` only that origin, merged in `Fetch.continueRequest`) and `credentials` (answered on `Fetch.authRequired`; `handleAuthRequests` is on wherever interception is, so a site asking without credentials shows its 401 page and the model is told). The timeline label of `browser_set` lists only the keys, never values. `browser_screenshot` takes `ref` / `selector` (clipped in page coordinates) and `format: jpeg` / `quality`; the gateway saves `.jpg` with the right MIME.
- Not taken: the cross-session tab pins, `tab keep frozen`, HAR, WebMCP, axe, React tools, recording, the DevTools inspect proxy (it needs a TCP listener), copying the user's Chrome profile.

## Refs

A ref is tied to a DOM node `(session, backendNodeId)`. A new snapshot of a node that still exists gives it the same ref, and numbers are never reused. A main-frame navigation (`Page.frameNavigated` without a parent) invalidates every ref of the tab, and an iframe navigation invalidates that frame's refs. Using an invalid ref fails with "re-snapshot". If a node is replaced but still exists in the same frame, it is matched again by role + name, only when that pair was unique in its snapshot.

## Dialogs and navigation

- `alert` / `beforeunload` are accepted from the event handler and reported in the next result.
- `confirm` / `prompt` stay pending. Input commands race their CDP reply against the dialog event, because a click that opens a dialog doesn't get its reply until the dialog is handled. Every tool except `browser_dialog` then fails with the dialog text.
- Navigation waits for the main frame's `load` lifecycle event, up to 30 s. A back/forward-cache restore (`frameNavigated` type `BackForwardCacheRestore`) sends no lifecycle events, so it counts as loaded.
- An action result says when the document changed (refs gone), or when only the URL changed inside the page.

## Gateway rules

- The ticket file is at `<data>/browser/tickets/<sid>.json`. The proxy binding (`proxy_access`), the `--home` rule and the local-only `browserUse.mcp` (rejected for remote peers in `serve_conn`) are the same as for computer use.
- Plan mode allows only the categories `navigate`, `snapshot`, `get`, `scroll`, `wait` (`browser_network` reads count as `get`, routes as `network`). Other calls return a tool error and don't start a browser.
- Host settings `browser`: `executablePath`, `persistentProfile`, `allowedDomains`, `deniedActions`, `ignoreHttpsErrors`. Denied categories are refused in every mode. A change of path or allowlist closes running browsers (the next call starts new ones and tells the AI). With `persistentProfile` the profile is `<data>/browser/profiles/persistent`, never deleted, and one session at a time may hold it (enabling in a second session fails with a clear error); it is ignored while an allowlist is set. `browser_upload` takes files inside the session's working directory or its download folder only (canonicalized).
- Page-sourced text (snapshot, get text/html/value, console) is wrapped in `YI_BROWSER_PAGE_CONTENT nonce=<random per grant> origin=<scheme://host>` markers and cut at 50,000 characters.
- `browser_open` accepts only `http(s)`; a bare port means `http://localhost:<port>` on the session host.
- Each call emits `BrowserUse` running, then completed / failed (with the URL it ended on). Calls are serialized per browser. Pause/stop bumps a per-session cancel counter that aborts an in-flight call, and a result that races a stop is reported as failed.
- Screenshots are saved as `uploads/<sid>/browser-*.png` and pruned with `computer_use::prune_images` (24 files / 80 MiB, `browser-` prefix only). Claude and Codex get the image block. Kiro gets the saved path instead (its CLI shows MCP images as base64 text). Codex's display copy goes through `display_result`.
- Profile: `<data>/browser/profiles/<sid>`. It is deleted when the browser is turned off (after `Browser.close`, retried while Chrome lets go of files) and emptied when it is turned on. The browser closes after 1 h without a tool call; the next call starts a new one and tells the model that tabs and refs are gone. Chrome is started through `proctree` (Job Object / process group), so it dies with the daemon.
- Adapters:
  - Claude: `mcp__yi_browser__*` is added to `--allowedTools`, and `can_use_tool` is answered by `Browsers::authorizes`;
  - Codex: `display_result` strips the image bytes;
  - Kiro: `--trust-tools @yi_browser/<tool>`;
  - other ACP tools (Qoder, CodeBuddy, Cursor, Antigravity): `session/request_permission` for a yi_browser tool is answered with allow-once while the browser is on and not paused (`acp::gateway_tool`). Only exact forms are recognized: the call name `mcp__yi_browser__<tool>`, the title `<tool> (yi_browser)`, or CodeBuddy's `DeferExecuteTool` with `toolName` `mcp__yi_browser__<tool>` in its input. A shell command that mentions those names still goes to the user;
  - Claude / Codex system prompts get `browser::model_hint`;
  - ACP tools get `browser::acp_notice` once per launch.

## Known limits

- Chrome's debugging port is on 127.0.0.1, so any process of the same user can connect to it and bypass the gateway. This was accepted for the first phase (proposal 7.4).
- The Windows private desktop for headless Chrome (agent-browser's `CreateDesktopW`) is not done. Tests ran from Session 0 (WMI), where no window can show.
- The allowlist's page script is best effort, as agent-browser says: with `eval` allowed, page code can restore the originals. Deny `eval` with an allowlist.
- The Linux Xvfb path is type-checked (`cargo check --target x86_64-unknown-linux-musl`) but was not run on a Linux host without a display.
- Headed mode under Session 0 (WMI test runs) starts and works over CDP, but no window is visible there.

## Tests

Real models (Windows, isolated yi-web on 127.0.0.1:8194): `scripts/browser/windows-model-e2e.mjs` serves an order form whose random code exists only on the page after a real submit (fill with Chinese text, select, checkbox, a confirm dialog, a cookie banner), then checks what the server received and that the model's answer contains the code. Approvals other than Kiro reading its own screenshot fail the run. `scripts/browser/windows-shots.mjs` captures each session's chat with the tool rows expanded. The e2e script also has the app open on the session while the AI works: the AI browser tab must open by itself and draw the page (`<tool>-acting.png`, `<tool>-live-N.png`), then a person navigates from the address bar and clicks and types (keys and committed IME text) on the canvas, which the fixture page reports back to the server (`<tool>-takeover.png`). Passed on 2026-11-17 with Kiro, Qoder, Cursor, CodeBuddy and Codex (both configured accounts, OAuth and API key), with no approval prompts. Claude (provider subscription expired) and Antigravity (one account unlicensed, the other out of quota) could not run on that machine. Entries of `YI_BROWSER_TEST_TOOLS` may be `tool=<accountId>`; with `ACCOUNTS=1` the Windows runner copies `accounts.json` and links the real `accounts` folder into the isolated home (removing the link before any cleanup). Accounts that switch Windows credentials (Antigravity) need a process in the user's logon session, so the runner starts from an interactive scheduled task rather than WMI.
