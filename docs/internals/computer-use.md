# Computer use (Windows first)

The Windows x64 yi-agentd embeds cua-driver 0.34.0 plus its MIT license. `runtime/computer-use/manifest.json` pins the archive, executable and license digests. Run `python scripts/prepare-computer-use.py` before a Windows build; CI does so in the daemon job, therefore the bundled/deployed daemon remains self-contained. No runtime network download or PATH override chooses the driver. First use verifies/extracts it below the daemon's data directory. Other targets compile without these bytes and report unsupported.

`computer_use::Desktop` owns the shared native runtime, a single desktop controller, per-session grants, current snapshot element tokens and cancellation. GUI execution belongs to the signed-in Windows session; Win32 session/input-desktop checks reject Session 0 and locked/secure desktops. 

Each provider starts `yi-agentd computer-use-mcp` using an owned ticket file. `--home` is passed only when the daemon itself runs with `YI_CONSOLE_HOME`, because it switches to a hashed pipe name; an installed daemon has none, and passing it made the proxy miss the daemon. This stdio proxy connects to the existing local IPC, not directly to the driver, and fails instead of starting a daemon (a new one would hold no grant). `computerUse.mcp` is rejected for remote peers in `serve_conn`; tickets are generated by the desktop manager, never returned to the frontend, and invalidated on reconfiguration/stop. A proxy can enumerate only the allowed tools, read the embedded gateway guide, and operate its currently granted window. Provider schemas omit window selectors: the gateway supplies the granted PID/HWND, while any explicitly supplied foreign selector is still rejected. Kiro’s display-only `__tool_use_purpose` field is removed before native dispatch. Window/desktop target escapes, stale or foreign element tokens, screenshot output paths, tools outside the allowlist and writes in plan mode are rejected. This does not isolate arbitrary same-user shell processes.

The ticket file is readable by the model's own shell, so the ticket alone does not authorize a proxy. `serve_conn` passes the IPC client's process id (named pipe client PID / Unix peer credentials, via `transport::PEER_PID`) to `Desktop::proxy_call`, which binds the grant to the first proxy and its parent (the AI tool). Another proxy is accepted only when the same tool started it, or after the bound proxy has exited; `Hub::launch` forgets the binding because the new tool process starts its own proxy. A Qoder model that had read the ticket once started its own MCP client; that path now fails with an error telling it to call the tools directly.

Scope is the whole desktop, as in OpenBot, which has only an on/off switch per agent and no window picker. Enabling takes no target. The gateway exposes the 25 desktop/app tools in `READ_TOOLS`/`WRITE_TOOLS` (window discovery, `launch_app`, window state/desktop capture, input, `hotkey`, clipboard) and leaves out browser CDP tools, `kill_app`, recording/replay, driver sessions/config/cursor themes and installers. The model passes `pid`/`window_id` itself; the gateway still strips `session` and `screenshot_out_file`, and keeps element tokens and capture ids per window (0 for `get_desktop_state`) so a token is only valid for the window it was read from. Window titles from `list_windows`/`launch_app`/`get_window_state` label the timeline, and the window of the last action is `lastWindow` in `computerUse.status`. Manual capture takes the full desktop. `computerUse.targets` (list_windows) stays for tests and diagnostics.

Model guidance (`guide!()` in `computer_use/mod.rs`) follows OpenBot's: shortest path, one read then act, `query` / `include_screenshot: false` instead of full re-reads, read `structuredContent` (refused/suspected_noop did not happen, unverifiable needs one check), foreground delivery from the start for Chromium/Electron windows, `press_key return` to submit, no own MCP client or ticket reads. It goes into the MCP initialize instructions, Claude/Codex system prompts (`model_hint`) and, for ACP tools that take no system prompt, a one-time `<system-reminder>` block in the first non-slash prompt after each launch with the server (`acp_notice`). The reminder also says earlier "tools missing" turns are outdated: a resumed Qoder session believed its own history over its current tool list. Measured on the WinForms fixture with Qoder (set text, click, read the check code): 25 s and 6 MCP calls in a fresh session, 44 s and 11 MCP calls in one whose history said it had no MCP tools; before, the Feishu task took 5 min 41 s and 43 Bash/Read calls.

The driver uses one directly owned MCP process in `--direct` mode, with vendor telemetry and update checks disabled. Requests are serialized. A cancellation watch invalidates requests waiting for the driver, and kills a pending owned driver after interruption; stopping an unrelated session must not cancel the active owner. Failed/interrupted actions are not replayed. Drivers are recreated after transport failures without replaying the previous action.

All four ACP providers receive the owned stdio server through the common MCP layer in ACP `session/new` / `session/load` `mcpServers`, including an explicit empty `env` list; a process-scoped `--trust-tools` list preauthorizes only `@yi_computer_use/<tool>` while preserving explicit user rules; the server config is separate from CLI arguments. Claude receives a process-scoped `--mcp-config`; Codex receives a process-scoped `-c mcp_servers.yi_computer_use=...` override. No global MCP file is modified. Enabling requires an idle supported chat session and relaunches its adapter using the existing external ID where available. The desktop grant merges an owned-MCP rule into Claude’s process-scoped `--allowedTools` (preserving user rules), so auto mode does not invoke its external classifier before `can_use_tool`. The callback also recognizes authorized gateway tools, while the gateway still enforces the active grant/target/read-only policy. User-configured tools and other permissions retain existing behavior.

`SessionInfo.computer_use` is default false and resets after daemon restart. Runtime grants are intentionally not restored. Enabling relaunches the tool at once (same tool session id) with the `yi_computer_use` entry. Turning off revokes the ticket and interrupts the turn; the entry's presence is part of the session's MCP fingerprint (`hub::mcp_fingerprint`), so the next message relaunches the tool without it, as OpenBot reloads a session when its Computer Use switch changes. Interrupt pauses and the next user message (`Hub::send` → `resume_if_paused`) resumes, unless another session took the desktop meanwhile; kill/delete/clear/mode switch revoke; ordinary client disconnection does not revoke a running authorized task. Pause clears element handles and releases control, resume requires fresh observation. Stop revokes before interrupting the provider. A returned driver result is not a success claim: refusal/no-op/unverifiable outcomes stay distinct.

Every action is emitted through `Hub::emit` as `ComputerUse` metadata, with a stable action ID for running/final updates. Screenshot bytes are saved as existing session image artifacts; persisted/broadcast events carry `ImageRef`, not base64. The model-facing MCP image is preserved. Codex's display-only copy removes image data so it does not inflate ToolResult/database records. A screenshot cannot be redirected by a model-supplied file path. Only desktop-prefixed checkpoint images are pruned to the latest 24 files / 80 MiB per session; user attachments are retained.

`ComputerUsePanel.tsx` is a compact per-session composer toolbar slot, Windows-only (all six AI chat providers on Windows x64), and uses `useBack` for its dialog. As in OpenBot it is only an on/off switch: the icon opens a dialog with enable, or turn off (`stop`) when enabled; there are no pause, resume or capture buttons, though the RPC actions remain. Control event revisions and low-rate status reads keep multiple clients in sync without screen polling. `ChatView` folds each gateway action into the AI tool's own call row (matched by the `yi_computer_use` server name in the tool name or title and the driver tool name, within the current turn), as OpenBot shows them as ordinary tool steps: the row is labelled with the desktop tool and window, flags unverified/interrupted/failed results, and shows the screenshots when expanded. Enable/pause/resume/stop become one-line notes. Only actions with no matching tool row (a manual capture) keep a standalone card. Images reuse the existing load/enlarge/save behavior. New UI strings are in both `computerUse` namespaces.

Validation: `cargo test` and focused gateway tests cover nested target escapes, image redaction, uncertain outcomes, queued-call revocation, current-snapshot input checks, unrelated-session cancellation and local IPC remote-peer rejection (including SSH bridge markers). `scripts/computer-use/windows-fixture.ps1 -Root <isolated-root>` creates an interactive WinForms target and records a native button callback. Optional `on-window-ready.ps1` starts an isolated daemon/web host. `windows-e2e.mjs` (and `windows-model-e2e.mjs`, `scripts/mcp/windows-providers-e2e.mjs`; all need `YI_CU_TEST_ROOT=<isolated-root>`, the providers test also takes `YI_MCP_TEST_PYTHON`) runs on Windows with Playwright Chrome and the real MCP proxy; it asserts actual UIA input/callback, model-facing images, image references, pause/resume/stop and desktop contention, and produces full-app screenshots and a JSON report. Set independent YI_CONSOLE_HOME and yi-web --data; never point tests at the production profile. Native/model and GUI tests must be reported separately; no mocked desktop screenshot is evidence of a native action.

Kiro CLI v2 serializes MCP ImageContent as base64 text ([upstream issue](https://github.com/kirodotdev/Kiro/issues/6292)). The Kiro model-facing result replaces image blocks with exact paths to the just-saved gateway screenshots and asks its built-in image reader to open those artifacts. Native file permission handling remains unchanged. Claude/Codex retain native MCP images. ACP display-only raw outputs recursively remove image bytes before persistence, preserving the tool result seen by the provider.

The host platform gate in `app/src/computerUse.ts` requires a known Windows x86_64 session host, structured mode and a supported AI provider. macOS/Linux/ARM/unknown hosts and Shell/Files/terminal sessions have no entry; a Mac or mobile client may control a Windows session. Generic external MCP does not inherit this platform restriction. The compact active toolbar offers capture, pause/resume and stop; stop remains available during capture. On mobile, the entry becomes an icon and capture/pause move into its dialog; a visible stop button remains in the composer to keep its toolbar on one row.
