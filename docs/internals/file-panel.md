# File panel

The session page's "workspace files" (`FilePanel.tsx`), also used standalone by Files sessions (see [sessions.md](sessions.md)), and the git / fs methods behind it.

## Layout

- With no file open it's a single tree column (`.file-panel.browse`, width `--tree-w`); opening a file widens it (`--panel-w`), with the editor on the left (tabs for opened files above it) and the tree on the right.
- File tree visibility (`wp-tree-<host>::<session>`) and the active sidebar view (`wp-view-<host>::<session>`: Files / Changes / Search) are stored per session so toggling the tree or switching views in one session doesn't affect other sessions.
- The chat area keeps at least 420px, and the session header and input box collapse their text when narrow via container queries on `.session-view`.
- "View changes" is no longer a separate page: `SessionActions.showChanges` sends `OPEN_CHANGES`, and the session page opens the file panel on "Changes".
- "Add to chat" sends an `INSERT_COMPOSER` event, and the Composer appends `@relative-path` to the draft.

## Tree

- The tree marks changes (M / U / D) from `git.changes` (with `diff: false`, statuses only, because running git diff per file is too slow in big repos), and dims git-ignored files, ignored directories (plus `.git`), their descendants, and open tabs (`.g-ign`) using the `ignored` list returned by `git status --ignored=matching`.
- The filter box uses `fs.search`.
- When a turn ends the tree refreshes, and open files without local edits are reread.
- Expanded folders are stored in localStorage `wp-exp-<host>/<cwd>` (missing ones are dropped quietly).
- Keyboard: VS Code's bindings (arrows, Home/End, Enter, F2, Delete) on a focus cursor separate from the open file; renaming a folder moves open tabs and expanded folders inside it.
- On Windows, `fs.list` must strip the `\\?\` prefix canonicalize adds (`fsapi::strip_verbatim`) before building child paths, otherwise child paths don't match the root and git paths (a "?" in the breadcrumbs, git marks lost); the frontend's `unverbatim` handles old records.
- `FilesView` breadcrumbs retain each path separator using a forward-only regular expression. Avoid regex lookbehind in statically imported frontend modules: macOS 13.0 WebKit rejects it during parsing, preventing the app from loading before any input handlers can run.

## Git: changes, diffs, history

- git operations are in `crates/yi-agentd/src/gitops.rs`. Paths are always relative to the repo root; absolute paths and `..` are rejected. Every git command runs with `GIT_OPTIONAL_LOCKS=0` (the panel polls status, which would otherwise take `index.lock` and break an agent's commit), and `git.changes` returns at most 10000 files (`total` is set when more were left out). Rename entries preserve `oldPath` across `gitops.rs`, `CommitDialog`, `FilePanel` discard/diff blob lookup, and `ReviewTab`, so staged renames commit and discard both paths cleanly. Untracked file diffs (`untracked_diff`) emit only the link target text for symlinks and reject files outside the repo root.
- Long lists (tree, Changes, tree filter results; over `VIRTUAL_MIN` = 150 rows) are virtualized like VS Code's list view: `Rows` gets the scroller (`treeBox`) and renders only the rows in view plus `OVERSCAN` above and below, with padding standing in for the rest. All rows share one height, measured from a rendered row (it's taller on phones). Keyboard moves scroll by row position, since the target row may not be in the DOM. 12000 changes went from ~181,600 page elements to ~900.
- Line counts `added` / `deleted` aren't affected by `diff: false`: tracked files are computed in one `git diff HEAD --numstat`, new files have their lines counted (null for binaries and files over 200KB). The Changes view shows +N −M to the right of each file and as a total at the top, and the diff of a single file is fetched with `paths` when it's opened.
- The Changes view supports three scopes: "Uncommitted" (working tree vs `HEAD`, via `git.changes`), "Branch" (`merge-base(base, HEAD)` vs working tree including untracked files, via `git.branchDiff`, with base branch selectable from `git.branches`), and (when the session has completed turn checkpoints with file changes) "Turn N" (`baseRef..endRef` via `git.refDiff`, read-only full-file diff reading both sides through `git.blob`). Clicking a turn's change chip in the chat footer opens the panel directly on that turn's diff. An opened working-tree file switches between "File / Changes" to see the full-file diff (`MergeDiff.tsx`), using `HEAD` or `mergeBase` as the left-side `git.blob`.
- Git actions in the Changes view (`GitOpsDialogs.tsx`): the top of the Changes list keeps a single minimalist underline scope strip (`Uncommitted` / `vs <base>` + diff line totals), while the bottom dock (`wp-git-dock`) pairs a T3 Code-style adaptive split button (`Commit & Push` / `Push ↑N` / `Pull ↓N` / `Merge → <base>` / `Fetch / Sync`, with dropdown actions for commit-only, push, pull, merge/squash, and fetch) with the cross-tool AI review button (`git.commit` with default-branch warning and inline "create new branch before committing", plus optional immediate push via `git.push`). Branch / worktree switching lives in a minimalist top context strip (`wp-ctx-bar`) directly below the file view tabs (shown whenever the folder is a git repo across Files, Changes, and Search, with a quiet right-side sync button showing `↑N ↓M`), opening a portalled, searchable 4-zone `BranchWorktreePopover` (`Worktrees | Local | Remote` underline tabs, pinned current worktree with bound session state, progressive-disclosure `···` lifecycle menus backed by `git.fetch`, `git.pull`, `git.merge`, `git.rebase`, `git.renameBranch`, `git.branchDelete`, `git.worktreeAdd`, `git.worktreeRemove`, and collapsible merged worktrees with safe batch cleanup via `git.worktreePrune`). Commit history defaults to collapsed, and per-file discard (`git.discard`) lives in the file context menu. Generic `ContextMenu` (`Overlay.tsx`) permits wheel scrolling inside the menu itself without dismissing it.
- Git worktree detection and switching: `git.worktrees` (`git worktree list --porcelain`) discovers all worktrees of the current repository, including ones created by an AI agent or in a terminal outside the session. `SessionView` keeps a per-session `panelCwd` override (`file-panel-cwd-<key>`) so switching worktrees remounts `FilePanel` cleanly with independent tabs and expanded folders; when a new worktree appears during polling, a lightweight banner offers one-click switching. When browsing a different worktree from the session's `cwd`, `@` references and `<yi-context>` pills send absolute paths so the main session's agent targets the right directory.
- Inline review comments (`MergeDiff.tsx`, `ContextRefBar.tsx`, `contextRefs.ts`): hovering a diff hunk or selecting diff lines exposes a "Comment" button that opens an inline popover (`Ctrl/Cmd+Enter` queues a `kind: "review"` context ref without stealing focus from the diff). Queued review comments appear in a summary bar above the composer and can be edited, cleared, or sent together in one prompt.
- Cross-tool read-only code review (`ReviewTab.tsx`, `ReviewInlineWidget.tsx`, `reviewState.ts`, `git.reviewScope`, `review_mcp.rs`, `adapters/review_guard.rs`):
  - The Changes dock's "AI Review" button (and commit-history hover / context menu actions in `GitHistory.tsx` for single commits or `<commit>^..HEAD`) opens `ReviewLaunchDialog` with per-tool model, reasoning effort, and Cursor model-parameter selection (`tools.models` / `tools.modelConfig`, persisted in `review-model-prefs`, forwarded to `session.create`) and four scopes: Uncommitted (`all` / `tracked` / `staged`), Compare branches (`base ← target` across local and `remoteBranches`, defaulting `includeUncommitted` to off), Commits (multi-select with server-side `git.log` search and recent-N presets), and Range (`A..B`, `A...B`, or single ref). Each scope resolves live file/line stats via `git.reviewScope` and supports file exclusion before launching.
  - Small scopes (`<= 25` files, `<= 1,200` changed lines, `<= 55,000` diff chars) pre-feed the unified diff directly inside `<yi-review-diff>` (listing any selected files whose diff was omitted—e.g., >200 KB or empty—so the reviewer inspects them via `yi_review` instead of treating a partial diff as complete); larger or multi-file follow-up inspections use the built-in strictly read-only `yi_review` MCP gateway (`review_scope`, `review_diff`, `review_read_file`, `review_grep` over local `review.mcp` IPC with PID + ticket binding and symlink containment checks), plus adapter-level read-only enforcement (`review_guard.rs` hard-denies mutations, restricts auto-allowed `sed`/`rg`/`git` options to verifiable read-only forms while sending `awk` and arbitrary scripts to `Ask`, and routes any ambiguous permission prompt in-place via `session.permission` + `<PermissionCard compact />`).
  - Launches create a first-class review side chat (`sideChat: true`, `review: ReviewSessionMeta`, opened on `side:<sessionId>` via `SideChatPane` -> `ReviewSidePane`) with permission mode locked read-only and archived in the parent session header's side-chat menu (closing the tab preserves history; explicit trash deletion removes it). `ReviewSidePane` offers a `[Findings | Process]` segmented toggle, live activity/stream banner, severity & dismissed filters, and a compact follow-up `Composer`.
  - Parsed `yi-review-json` findings also drive Changes sidebar issue-count badges + an "Issues only" filter (`.wp-review-ov-bar`), a Diff top ribbon (`.wp-diff-review-bar`), and embedded CM6 `block: true` portal cards (`ReviewInlineWidget.tsx` via `MergeDiff.tsx` `inlineReviewsField`) showing severity, suggestion, inline follow-up drawer (`<yi-review-ref ... />` tags bidirectionally synced between Diff card threads and `ReviewSidePane`), inline approval fallback if ever triggered, and unified one-click adoption into the main session's `ContextRefBar` queue (`reviewSource`, `reviewFindingId`, `sideSessionId`). Removing an un-sent pill restores `open` disposition while sending keeps it `adopted`.
- Opened diffs (working tree vs HEAD, a commit vs its first parent, comparing two files) are full-file diffs (`MergeDiff.tsx`, `@codemirror/merge`): by default they open in single-file inline mode (`unified`, `wp-diff-mode`) with the full file expanded (`wp-diff-fold` false), showing deleted lines in red above added lines in green, syntax highlighting on both, and direct editing + Ctrl/Cmd+S saving on working-tree files (commits, deleted files, and truncated / non-UTF-8 files stay read-only). Added files highlight all lines in green inside `unifiedMergeView`, while purely deleted files render in a read-only single editor with red line markers (`wp-merge-all-del`). The look matches the chat diff preview (`DiffView`): faint line tints (`--df-add-line` / `--df-del-line`), a 2px bar in the gutter, no +/- signs, dimmed deleted text, and `highlightChanges: false` so there are no word-level boxes. The chat's diff preview (`DiffView`), `PaneDiff` and the context-ref popup use the same tints and bars. Side by side (`split`), the two editors scroll themselves and stay synced (`syncScroll`), and the divider drags to resize (double-click resets; the ratio isn't saved, as in VS Code). Hovering any diff hunk reveals a floating "Add to chat / Copy" bar (`wp-hunk-bar`), and `PaneDiff` offers the same actions on each `@@` header. When the git status changes (the 10 s poll, end of turn), the old blobs stay on screen until the refetch lands (`staleBlobs`), so the open diff isn't swapped for the loading state and remounted. When the text of an open diff changes, `MergeDiff` patches the editors in place with the changed span (`patchDoc` / `patchOriginal`) instead of rebuilding, so the scroll position and undo history stay.
- Binary, oversized or unreadable sides, older daemons without `git.blob`, and tool snippets outside git fall back to the hunk-only `PaneDiff`. Before git status comes back, don't use the snippets recorded by tools in the session as a diff.
- Caching, like VS Code's Source Control view: the last git status per host + directory is cached in memory (`gitCache` in `FilePanel.tsx`), so a remounted panel shows it at once and refreshes quietly. The root path and top-level listing are cached the same way in `rootCache`, since the Changes list and the tree are laid out against the root. The commit history caches its first page and each commit's file list (`logCache` / `showCache` in `GitHistory.tsx`) and doesn't wait for git status (it only hides once status says the folder isn't a repo).

## Editor and tabs

- The editor is CodeMirror 6 (`CodeEditor.tsx`; folding, auto-closed brackets and VS Code's multi-cursor bindings). Language packs are lazy-loaded by file name through `@codemirror/language-data`, and highlight colors come from `--hl-*` variables on `.file-panel`. Both `CodeEditor` and `MergeDiff` wrap their views in `isolation: isolate` so CodeMirror's internal `.cm-panels`/`.cm-tooltip` layers never escape above page modals, and mount a custom floating top-right Find & Replace panel (`EditorSearchPanel.ts`, click-through host overlay with inline `Aa`/`ab`/`.*` toggles, live `current / total` match counter, `Ctrl+H` / `Cmd+Alt+F` collapsible replace row hidden in read-only views, and IME keydown guards).
- Right-click in the editor (`CodeEditor` and `MergeDiff`) opens its own menu (`menu` prop, items from `editorMenu` in `FilePanel.tsx`) instead of the global edit menu: cut / copy / paste / select all through the CodeMirror view, find, go to line, add selection to chat (`ADD_CONTEXT_REF`, also triggered by the floating chip above a selection or `Ctrl/Cmd+L`), copy `rel:12-20`, word wrap, fold / unfold all. Like VS Code, right-clicking outside the selection moves the cursor there first. In a diff, "add selection to chat" sends the same diff snippet as the floating chip (deleted lines included, `addSelection` on the menu context), and the old (left) side has no "copy path with line", since its line numbers aren't the file on disk's. Word wrap is one setting for the whole panel (`wp-wrap`), also toggled with Alt+Z in the editor and from the "⋯" menu.
- CodeMirror joins lines with `\n`, so the editor writes the draft back with the file's own line ending, and indentation is detected per file (`app/src/textFormat.ts`).
- `fs.read` flags files that aren't valid UTF-8 (`notUtf8`) and those open read-only, since saving the lossy text would corrupt them.
- Writing files goes through `fs.write`: saving sends the `modified` seen at read time, and if the agent changed the file meanwhile the write is refused and the user chooses between reloading from disk and overwriting. `fs.delete` only deletes files and empty folders.
- Open tabs and the current file are stored in localStorage `wp-open-<host>/<cwd>` and restored once the panel mounts and has the root (unreadable files are silently dropped).
- An inline `+` button (`.wp-tab-new`) immediately follows `.wp-filetabs` to create a new untitled tab (`untitled:Untitled-N`, titled by its first line) with a single click, staying reachable even when tabs overflow and on mobile; `Ctrl/Cmd+Alt+N` or double-clicking empty tab bar space (when not overflowing) or the empty editor area also creates one. Its text lives only in memory (`untitledCache`, per panel key, so it survives remounts but not an app restart, unlike VS Code's hot exit), and saving asks for a path relative to the root (or absolute), writes with `createOnly` and asks before overwriting.
- The outline is `app/src/outline.ts` using per-extension regexes, no syntax tree.
- Code navigation (`EditorCodeNav.ts`, `CodeNavOverlays.tsx`, `crates/yi-agentd/src/code_nav.rs`):
  - `Ctrl+Click` (macOS `Cmd+Click`), `F12`, `Shift+F12`, and top entries in `editorMenu` provide Go to Definition, Definition Picker, in-place Peek References, and path/import/URL jumps across both `CodeEditor` and `MergeDiff` (including deleted chunks in unified diff, with per-side file paths and revisions in split/compare diffs).
  - Hovering with `Ctrl`/`Cmd` evaluates only the local Lezer `syntaxTree` (no RPC until clicked). Clicking a definition site directly opens Peek References (`atDefinition` branch), with an "Open in Search" handoff into `GrepPanel`. Pending RPC requests are invalidated on dialog dismiss or editor/mode switches, and `openFile` / history stepping commit only after the target opens without cancellation or failure.
  - All `col` / `len` positions across `nav.definition` and `nav.references` use 0-based UTF-16 code units matching CodeMirror 6.
  - Backend logic sits behind the `NavProvider` trait (`BuiltinNavProvider` using `.gitignore`-aware incremental caching with strict canonical workspace symlink containment on all reads, unsaved draft content as the single source of truth for the active buffer, lexical inner-scope binding precedence over shadowed imports, default export/re-export resolution, `tsconfig.json` / `jsconfig.json` path aliases, Rust submodule/`self`/`super` directory probing, container-aware scoring, and $O(N)$ per-hit reference filtering), with `nav.references` routed over `BULK_METHODS` and graceful fallback for older daemons (`outline` / `fs.search` / `fs.grep`).
  - `.wp-head` houses a 50-entry Back/Forward history stack (`Alt+←`/`Alt+→` on Windows/Linux, `Ctrl+-`/`Ctrl+Shift+-` on macOS, plus mouse side buttons 3/4) preserving diff side and compare target.
- Markdown preview is `MdPreview` in `FilePreview.tsx`: it renders top-level blocks with an `<a class="md-ln" data-line>` anchor before each, and both split-view scroll sync and outline jumps interpolate between anchors; relative-path images become `data-src` and are fetched via `fs.read`.
- Images are fetched as base64 with `fs.read` and `image: true`.

## Search and replace

- Content search goes through `fs.grep` (file-by-file in Rust with the `regex` crate, no rg dependency; literal unless `regex`, plus `include` / `exclude` comma-separated globs with VS Code's semantics in `glob_set`, and `paths` for open files only).
- Replace follows VS Code's search view (`GrepPanel.tsx`): `fs.replace` shares `Matcher` with `fs.grep` so both see the same matches, replaces only the listed results (line + column), skips files whose `stat` from the search no longer matches, keeps every byte outside the matches, and returns the old text for one-step undo (written back with `fs.write`'s conflict check). The open file with unsaved edits is replaced in its draft via `dryRun` + `content`.

## Upload, download, open

- Uploads use `fs.upload`, downloads and PDFs use `fs.read` with `raw: true` (all limited to 50MB).
- `fs.open` (open with the system program / reveal in file manager) only accepts local connections, and the frontend only offers it for the local host.
- The Tauri window has `dragDropEnabled` off so HTML drag-and-drop gets system files (and internal HTML5 `draggable` rows/tabs stay unbroken). On Windows Desktop (WebView2), `app/src-tauri/src/dropfiles.rs` resolves dropped files' real disk paths via `chrome.webview.postMessageWithAdditionalObjects` (`ICoreWebView2File::Path`) and emits them over `drop-paths`.
- External file drops on a session's chat area (`.chat-stage`) open the dropped files (including images and local directories) sequentially in `FilePanel` via `openFilesInPanel` (`takeOpenFiles` FIFO queue in `store.ts`) without touching `Composer`. Non-image external files dropped on the main session's `Composer` both insert `@path` references and open in `FilePanel`, whereas images dropped on `Composer` remain inline chat attachments only. On local hosts with resolved paths, the original disk files are opened directly (HTML preview remains scoped to workspace `root`); on remote hosts, macOS/Linux, or `yi-web`, dropped files upload via `session.attachFile` first. Saved tab restoration keeps external absolute file paths open (filtering out other sessions' temporary `uploads/<sid>/files/`).

## Browser tabs and HTML preview

- Browser tabs are in `Browser.tsx`, with tab keys `web:<url>` (`web:file:<absolute path>` is an HTML file on the host), stored in tabs like any other tab; remote localhost URLs go through `ports.forward` first.
- HTML previews go through `ClientHub::serve_preview`: `preview.root` exchanges a directory for a random token, and both the Tauri custom protocol `ahfs` and yi-web's `/fsv/<token>/<relative path>` map to `fs.read` raw, reading only the token's directory (.. rejected).
- The preview iframe has no allow-same-origin, and external URLs may not share the app's origin, so pages can't reach `hub_call`.
- On the Windows desktop app, `http(s)` tabs are native child webviews of the main window (`app/src-tauri/src/webtab.rs`, `components/NativeWeb.tsx`) instead of an iframe, so sites that forbid framing work and the address bar follows links, redirects and `pushState` (via title changes). Everywhere else (yi-web, Android, macOS, Linux) and for `web:file:` previews it stays an iframe; `NATIVE_WEB` decides. On mobile apps, non-`file:` browser tabs also offer a one-click handoff (`openInAppBrowser`, toolbar maximize button and `.wb-tip` banner) to the native full-screen in-app browser so sites that block iframes or need full navigation still open inside the app.
  - `Window::add_child` needs tauri's `unstable` feature, enabled in `Cargo.toml` for Windows only: it also turns the main webview into a child of its window, which hasn't been tested on macOS / Linux.
  - Layout: `NativeWeb` renders a placeholder and, every third animation frame, sends its rect (times the app zoom) to `webtab_bounds`; one request in flight, only the newest pending one sent.
  - App UI over the view: a native view paints over the whole main webview. `coverOf` samples `elementFromPoint` on a ~28 px grid of the placeholder and, for each hit, takes the outermost ancestor that paints something (background, shadow, border, backdrop filter), so the context menu's transparent scrim doesn't count but the menu does. Those rects (plus 10 px for shadows) are cut out of the view's window region (`SetWindowRgn` on the WebView2 controller's parent HWND), so menus, toasts and popups show through and take real clicks while the rest of the page stays live. Over 60% covered (a modal and its backdrop): the view is swapped for a `CapturePreview` JPEG (`webtab_capture`, a fresh one replacing the one cached every 2.5 s) until it closes, as VS Code's integrated browser does. `data-shown` on the placeholder says which (`1` live, `h` with holes, `0` hidden or picture).
  - Lifetime: unmounting only hides and parks the webview by `${hostId}|${tab}` (`pool`, at most 6, oldest closed first), so switching tabs or sessions doesn't reload pages. `Browser.tsx` keeps a view identity (`ident`) that changes only when the panel switches tabs, not when the tab key follows the page or the address bar. File panels register their open web tabs (`registerWebTabs`); a webview whose tab is closed is closed instead of parked. `webtab_reset` at frontend load closes leftovers of a previous load.
  - Navigation updates the tab key (`selfNav` in `Browser.tsx` keeps that from re-resolving the tab); forwarded remote ports are mapped back to the host's own `localhost:<port>`. `target=_blank` / `window.open` open a new web tab.
  - Safety: Tauri's ACL rejects IPC from remote origins, so the risk is the child reaching a local origin. `on_navigation` allows only `http(s)` and `about:blank`, not the app's origin and not the `*.localhost` hosts of custom protocols (`ahfs`, `ipc`, `asset`, `tauri`); the capability is scoped to `webviews: ["main"]`; the app's CSP has `frame-ancestors 'none'` so a page can't frame the app either.
  - Test: `scripts/browser/windows-webtab-e2e.mjs` runs a debug build with a test identifier and WebView2 remote debugging and drives both webviews over CDP (needs an interactive desktop).

## Side chat tabs

- Side chats open in the right panel alongside code/diff/web tabs with tab key `side:<sessionId>` (`SideChatTab.tsx`, `isSideTab`). Opening a side chat hides the file tree (like `aiweb:`) so the conversation gets room; the tree can be toggled back anytime.
- Multiple side chats can stay open in parallel tabs (running tabs show a blue status dot). Closing a side chat tab with no messages deletes its session automatically; closing a used one only closes the tab and leaves it reopenable from the parent session header's side chat menu.
- When tabs are open, the inline `+` button next to the tabs creates a new untitled file directly, while the right-side `sideChat` button opens a menu for creating a new side chat (same tool or another installed AI tool) or a web tab (when no tabs are open yet, the `+` button offers all three).
