# Frontend UI

Look and behaviour of the frontend outside the file panel and terminal: chat timeline, theme, fonts, sidebar, links, overlays, i18n.

- Content-Security-Policy: the main window's policy is `app.security.csp` in `app/src-tauri/tauri.conf.json`. Tauri sends it as a header on the app's HTML (packaged builds only; `tauri dev` proxies the Vite server, which gets no CSP) and adds hashes for its own init scripts to `script-src`; `dangerousDisableAssetCspModification: ["style-src"]` stops it adding a style nonce, which would cancel `'unsafe-inline'`. yi-web reads the same object at compile time (`csp()` in `crates/web/src/main.rs`), adds `frame-ancestors 'none'`, and sends it on HTML from dist only; host files under `/fsv/` keep their own rules inside the sandboxed browser-tab frame. `script-src 'self'` with no `'unsafe-inline'`/`'unsafe-eval'` is the point: HTML that slips into `innerHTML` (chat Markdown, Markdown preview, Mermaid) can't run inline scripts or `on*=` handlers. The rest is a list of what the app loads: `style-src 'unsafe-inline'` (React style attributes, CodeMirror / xterm / Mermaid `<style>`), `img-src data: blob: http: https:` (host images as data URLs, diagrams as blobs, web images in chat on click), `connect-src ipc: http://ipc.localhost` (Tauri IPC; `ipc:` on macOS/Linux, the http form on Windows/Android) plus `'self'` (yi-web's WebSocket), `blob: data: http: https:` (`saveImage` fetches), `frame-src blob:` (PDF) `ahfs: http://ahfs.localhost` (HTML preview) `http: https:` (browser tab). Adding a new kind of source (a worker, wasm, a new custom protocol, an inline `<script>` in index.html) needs a matching directive; check DevTools for `securitypolicyviolation` in both the Tauri build and yi-web.
- The chat area imitates Claude Code's timeline (`ToolLine` in `ChatView.tsx`): `toolName()` normalizes tool names to Bash / Read / Update and the like, and `toolKind()` classifies the result summary. Unknown tools from a new tool show their raw name, with the summary falling back to "first 3 lines of output".
- Tool summaries in the chat must handle every tool's format: Cursor's results are JSON (possibly wrapped in another string), Kiro's are wrapped in `{"items":[{"Json"|"Text":…}]}`, and failed commands only return `exit code: N`. All of this is handled in `parseOutput` in `ChatView.tsx`.
- Reply display style (system settings "Chat appearance" or the toggle at the top right of the session page, stored in localStorage `chat-style`): the default "compact" groups adjacent thinking and tool calls under a one-line summary title, expanded while running; "Claude Code" is the original dot timeline.
- Raw HTML in replies keeps its formatting (`<br>`, `<details>`, `<kbd>`, tables) but loads nothing by itself (`sanitizeChat` in `util.ts`, a separate DOMPurify instance so the file preview and Mermaid aren't affected): `<img>` becomes the same click-to-load `md-rimg` placeholder as `![](…)` (data: images stay inline); `<style>`, `srcset`, `poster`, `background`, `ping`, `src` on anything but `<img>`, `href` on anything but `<a>`, style attributes with `url()` / `image-set()`, and inputs other than task-list checkboxes are removed. Web images loaded on click use `referrerPolicy = 'no-referrer'`. The Markdown file preview (`renderMdLines`) still loads remote images, like VS Code's preview.
- Images in reply text (`![](…)`): `renderMarkdown` in `util.ts` doesn't output `<img>` but a `<span class="md-rimg" data-kind data-src>` placeholder, filled in by `hydrateImages` in `chatImages.ts` (`ChatView` provides the host and cwd via `ImgContext`). Files on the host (absolute, relative to cwd, `file://`) are read directly via `fs.read` with `image + strict` on the local host; remote hosts show a placeholder first, and on click `probe` gets the size and `askConfirm` confirms before downloading. Public URLs are always loaded by the current device only on click, so opening a chat never requests third parties. `strict` only accepts real images by file header, so a model referencing something like `~/.ssh/id_rsa` in a reply can't have it read out. In chat mode, Claude (`--append-system-prompt`) and Codex (`developerInstructions`, which overrides the same setting in config.toml) get `adapters::IMAGE_HINT`, telling the model to show images to the user as Markdown images with absolute paths; ACP tools have no system prompt entry point, so they don't get it.
- The UI theme is in `app/src/theme.ts`: choosing light / dark sets `data-theme` on `<html>`. Dark variables in styles.css must be written twice: `@media (prefers-color-scheme: dark) { :root:not([data-theme='light']) … }` and `:root[data-theme='dark'] …`. In JS, check for dark with `isAppDark()`, not matchMedia directly.
- Scrollbars: one global rule at the top of `styles.css` (`::-webkit-scrollbar`: 4px rounded slider inside an 8px bar, colors from `--sb-thumb*`), desktop pointers only. Like VS Code (`scrollableElement.ts`), the slider shows while the mouse is over a scrollable element (every scrollable ancestor of the pointer, `data-scroll-hover`, cleared 500ms after leaving) and while it scrolls (`data-scrolling`, 800ms); both set by `scrollbars.ts` because a `:hover` rule doesn't work, Chromium doesn't repaint scrollbars on hover; the tmux scrollbar in `TerminalView.tsx` does the same with a `scrolling` class. Tweak colors per area by overriding `--sb-thumb*` (the terminal does); don't use `scrollbar-width` / `scrollbar-color` except `none` to hide, since in Chromium they override the webkit styles. Playwright headless hides scrollbars by default; pass `ignoreDefaultArgs: ['--hide-scrollbars']` to see them in screenshots.
- The UI font stack starts with `system-ui`, which lands on Microsoft YaHei UI on Chinese Windows. Don't bundle web fonts.
- Font sizes are per-device preferences in `app/src/fontPrefs.ts` (localStorage `ui-font`), split like VS Code's chat / editor font sizes: the chat size sets `--fs-body` / `--fs-chat` / `--fs-input` / `--fs-code` (replies in both styles, headings, user bubbles, input box, code blocks), the editor size sets `--fs-editor` / `--lh-editor` (CodeMirror, `MergeDiff`, `PaneDiff`, Markdown preview). New text in those areas must use these variables (or offsets from them), not fixed px; 0 means the stylesheet default. Font families work like VS Code's `chat.fontFamily` / `editor.fontFamily` / `terminal.integrated.fontFamily`: comma lists typed by the user, quoted by `fontList()` and put in front of the built-in stacks (`--font-chat` = user list + `--font`, `--font-editor` = user list + `--mono`, the terminal's xterm `fontFamily` from `termFontFamily()`), so a missing font falls back to the default; empty means default. Chat text and the input box use `--font-chat`; CodeMirror, diffs and `.md code` use `--font-editor`; other `--mono` uses (paths, hashes, badges) stay fixed. UI zoom is the desktop app's page zoom (`getCurrentWebview().setZoom`, 1.2× per step like VS Code, Ctrl/Cmd + = / - / 0, needs `core:webview:allow-set-webview-zoom`); the browser build and phones keep their own zoom.
- Preferences (`PrefsView.tsx`) follow VS Code's settings editor: all sections on one scrolling page, with a sticky table of contents on the left (`SECTIONS`) that jumps to a section and highlights the one in view; hidden below 760px. A new setting goes into an existing section's card as a `PrefRow` (title + description left, control right); add a section only for a new category, and keep both the contents and the headings in `SECTIONS`. Single-card sections drop the card title, the section heading names them.
- Sidebar styles: the "Sidebar" section at the end of `styles.css` overrides everything in one place: width 244px, row height `--side-row-h` 32px, font size `--fs-side` 13px, text about 14px from the left. Change the sidebar there, not with scattered rules earlier. Structure is host header → directory subheading → session rows. Host-related entries (history, files, terminal, usage, host settings) all live in the host row's "…" / context menu (`hostMenu`); don't add buttons to the list. Session rows are the tool icon in its own color + grey title (darker on hover / selection) + time on the right; only running / awaiting approval / errored replace the time with a status. The sidebar scroll area shows no scrollbar. The filter box doubles as the entry to message search (Enter jumps to the search page). Ended sessions (exited / error) idle longer than the threshold fold behind a muted "Show more (N)" row at the end of their own directory (not a host-wide bucket; text in the title column, becomes "Show less" at the end once expanded, as in Codex / ChatGPT); pinned sessions and search results never fold. Layout (by directory / by time) and the threshold (1–30 days or never, default 3) are device prefs in localStorage `side-prefs` (`sidePrefs` / `useSidePrefs` in `Sidebar.tsx`), layout toggles with the clock / folder button in the host header (not in a menu, so it is one click), threshold is set in Preferences. In the by-directory layout the host header also has a fold-all / unfold-all button (folds every directory while any is open; writes the same `fold-dirs-<host>` list as folding a single directory).
- Sidebar width: dragging `.side-resizer` in `Sidebar.tsx` writes `--side-w` on `.sidebar` (244–480px, localStorage `side-w`); desktop widths only.
- New sessions remember, per tool, the last UI (chat / terminal), permission mode, model and thinking level (localStorage `new-session-prefs`, `NewSession.tsx`) and restore them when switching tools; remembered values the current tool or model doesn't support fall back to defaults.
- Tool badges (`ToolBadge`) use each tool's own logo (Claude Code uses claude.ai's starburst, Codex uses ChatGPT's OpenAI flower); shapes come from `@lobehub/icons` (MIT) and are inlined in `Icon.tsx`.
- The history page can be limited to one directory (`View.history.cwd`, including subdirectories), entered from a directory row's context menu in the sidebar.
- Clicks on `<a href>` in the page are intercepted by `guardLink` in `main.tsx`: external URLs open through `openUrl` (system browser on desktop; on the mobile app, the opener plugin's `inAppBrowser`, i.e. Android Custom Tabs), and relative paths etc. are blocked, so nothing navigates inside the app window. Right-click / long-press on a link is `linkMenu`: open, "open in another browser" on mobile (`openUrlExternal`, calling `YiConsoleAndroid.openExternal` injected by MainActivity to show the system chooser; http/https only), copy link. The mobile capability must include `opener:allow-default-urls`, otherwise you get "Not allowed to open url". Components that handle links themselves call `preventDefault`; download links carry the `download` attribute.
- The frontend no longer uses `prompt` / `confirm` / the browser context menu: use `askText`, `askConfirm` and `openMenu` from `components/Overlay.tsx`. Session actions live in `components/SessionActions.ts`, shared by the session page menu and the sidebar context menu.
- Code comments are in English. The daemon's error messages are in Chinese (translated for the English UI by `app/src/i18n.ts`). UI text is bilingual Chinese/English via i18next: strings live in `app/src/locales/{zh,en}/<namespace>.json` (one namespace per source file, registered in `locales/index.ts`), and code does `const t = getT('<namespace>')` then `t('key', { name })` (named `tx` in files where `t` is already a local). Chinese is the primary language: its files define the keys, and `npm run i18n:check` (part of `npm run build`) regenerates `locales/resources.d.ts` so tsc rejects unknown keys and missing / misspelled `{{placeholders}}`, then runs `i18next-cli status` (en has every key) and `i18next-cli lint` (placeholders match between languages; new hardcoded JSX text fails, existing cases are in `i18next-lint-baseline.json`). Plurals use i18next's `key_one` / `key_other` with `count`. Don't build sentences by concatenating translations or template strings; give the whole sentence one key with placeholders. The language is stored in local localStorage `ui-lang` (follow system / Simplified Chinese / English) and switched in system settings; `useLang()` in `App` redraws the whole UI. Every new user-visible string needs both languages, not just Chinese: add the key to both JSON files. Text built inside `useMemo` must include the lang from `useLang()` in its dependencies, or it won't update when the language changes.
- Diagrams in chat replies: `renderDiagramMarkdown` in `util.ts` recognizes `mermaid` fences (including nested lists/quotes) and returns sanitized placeholders plus source/closing-fence metadata. `ChatMarkdown.tsx` retains portal target nodes by block order across Markdown redraws, so later streaming text does not remount completed `MermaidBlock` components. While a fence is still streaming the block shows a spinner instead of the half-written source (the Source tab still shows it); unclosed fences in finished or interrupted replies show the source. `mermaid.ts` lazy-loads the pinned Mermaid 11 runtime (the app targets ES2021), serializes renders, ignores stale component results, and caches up to 32 source/theme/font combinations. Theme and font preference changes rerender diagrams. Sources are limited to 30,000 characters and graphs to 300 edges (Mermaid's edge-limit error maps to the same "size limit" message); that is the only filter. Every diagram type and all syntax pass, including frontmatter / `%%{init}%%`, HTML in labels, `classDef` / `style` and `click`: `securityLevel: 'strict'` plus the `secure` key list keep directives from turning on HTML labels or click handlers, the main window's CSP blocks any injected inline script or handler, and the output is sanitized and shown as an `<img>`. Known gap, accepted: image nodes with remote URLs (`A@{ img: "https://…" }`) are fetched while the diagram renders in the page, whereas chat images load only on click. SVG output is sanitized and displayed through blob-backed images, isolating diagram styles/links from the app. The inline header is a single compact row (32px desktop, 40px on coarse pointers), with Diagram/Source toggle buttons and labelled copy/fullscreen/download icons; download uses `openMenu` for SVG/PNG and inherits its Android-back handling. The fullscreen viewer registers `useBack`, traps focus, supports Escape, +/−/0, wheel/pinch zoom and drag/pan. SVG/PNG exports use `saveImage` (native save dialog on desktop, browser download fallback); PNG rasterization is capped at 8192 pixels per axis and 16 million pixels. Message storage, reply copy and Markdown exports retain the original Mermaid source. Claude/Codex receive Mermaid output guidance through the existing `IMAGE_HINT`; ACP has no system prompt entry point. Browser regression fixture: `app/tests/diagrams.html` (Vite), driven by `app/tests/diagrams.mjs` via windows-remote. On memory-constrained machines use `NODE_OPTIONS=--max-old-space-size=1536 npm run build`.

- Windows Computer Use adds per-session window selection/control and checkpoint image activity cards, using the existing image viewer and Android back handling. The picker traps keyboard focus and restores it on close. See [computer-use.md](computer-use.md) for driver, grant and provider behavior.

- Generic host MCP settings use `McpSettingsCard.tsx` and bilingual `mcpSettings` namespaces. Its editor registers `useBack`, uses JSON arrays/maps to preserve exact process arguments, and keeps masked secrets unchanged. Computer Use is a compact `Composer.desktopControls` slot gated by the session host platform, not the client platform.
- The composer model picker uses a compact settings menu when a model reports adjustable parameters: Fast is a direct switch, Context Window and Reasoning Effort open choice submenus, and Model opens a searchable model list. Cursor options come from ACP and keep their original parameter ids; unsupported/single-choice options are hidden. Claude/Codex retain their existing effort RPC. Desktop submenus are portalled to the body, flip left when space is limited, and clamp to the viewport; leaving the parent with the pointer does not close them. Mobile uses one bottom sheet with a back header for each level. Escape/Android back close the child level first; clicking outside closes the picker. `app/tests/cursor-model-picker.mjs` covers RPC values, aliases, context changes, model search, viewport bounds, keyboard/back handling and mobile navigation.
- Choosing a Cursor model or parameter never waits for Cursor: the daemon answers from its cache and the process switches before the next prompt. `modelConfigPending` is set only while an uncached model's parameters are read; the compact menu then shows "Reading this model's parameters…" with the model row still usable, and the trigger shows no spinner. Unset values show as "Default". The browser fixture's `?delayed` case covers a cold model and instant cached controls.
