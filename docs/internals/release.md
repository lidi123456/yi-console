# App release, self-update and Android

- App self-update (`app/src/update.ts`, UI in `components/AppUpdate.tsx`): desktop uses tauri-plugin-updater behind the `update_check` / `update_install` commands (`app/src-tauri/src/updater.rs`); Android uses the `YiConsoleAndroid.updateCheck` / `updateDownload` bridge in `MainActivity.kt`, which answers through `window.__yiUpdate`, verifies the APK's sha256 and opens the system installer (`REQUEST_INSTALL_PACKAGES` is added by `src-tauri/build.rs`). Both read manifests from the latest GitHub release (`latest.json` / `latest-android.json`, written by `scripts/release-manifest.mjs`); the repository URL is in `tauri.conf.json` and `MainActivity.kt`. The version comes from the `v*` tag (`scripts/set-version.mjs` in CI). To raise the committed version, run `node scripts/set-version.mjs v<x.y.z>` and commit; it updates `Cargo.toml`, `app/src-tauri/Cargo.toml`, `tauri.conf.json`, `package.json`, and the workspace entries in `Cargo.lock` / `package-lock.json`. Don't edit these by hand. A failed check (no release yet, private repository, no network) counts as "no newer version", for manual checks too; only install errors are shown.
- Android's `MainActivity` comes from `app/src-tauri/android/MainActivity.kt` in the repo (`gen/android` is generated and not checked in; CI copies it over after `tauri android init`, together with the launcher icons in `app/src-tauri/icons/android`, which would otherwise stay as whatever an earlier init left in `gen/android`). In edge-to-edge mode the system no longer shrinks the window for the IME, so it pads the bottom of the content by the IME inset (minus the navigation bar height the page already reserves via safe-area). The chat area's `ResizeObserver` keeps it pinned to the bottom when it gets shorter. The back key / back gesture is handed to the page's `window.__yiConsoleBack()` (`app/src/back.ts`): first close the topmost dialog, menu, image viewer or file / terminal panel registered with `useBack(active, close)`, then collapse the command palette and the left navigation (drawer, staying on the current page), then `goBack()`; when there's nothing left, first show "press again to exit", and only a second press within 2 s makes the page return false so the app calls `finish()`. Anything new that covers the page must register with `useBack`. QR pairing doesn't use a native plugin (Tauri's official barcode-scanner relies on ML Kit from Google Play services, which crashes on opening the camera on phones in mainland China); instead `QrScanner.tsx` uses `getUserMedia` + jsQR in the page. When the WebView needs the camera, wry requests CAMERA from the system, and the manifest permission is written into `gen/android` by `src-tauri/build.rs` during Android builds. On mobile, the "+" in the input box first asks "Photos" (`accept="image/*"`, opens the gallery) or "Files".
- Release Tauri and Android packages are built in CI (`.github/workflows/build.yml`). An explicitly requested native Android build can use `scripts/build.py android` on a machine with the SDK, NDK, Java and Rust targets already installed; do not force local builds on machines missing these prerequisites.
- `scripts/build.py` is the build shortcut (Python 3.9+, no Python dependencies). Local mode selects frontend, Rust binaries or bundled plugins; `--ci` dispatches the build workflow through `gh`, optionally watching and downloading artifacts. The selected ref must already contain the script and workflow changes; local edits are never uploaded. `--dry-run` does not execute subprocesses. The package catalog and CI matrices live in this script; the plan job calls `--plan-ci` to write `daemons`, `desktop`, and `android` outputs. Desktop selections keep every SSH daemon target, while Android-only skips both matrices. Empty manual `packages` preserves `only_daemons` / `windows_only` behavior (the latter omits macOS daemons); explicit selections cannot be combined with legacy flags. Tag pushes always select all. A unique `build_id` in the run title lets the shortcut find its own dispatch, even with concurrent builds. Manual runs only upload artifacts; tag builds keep the existing signing requirements and release job.

- Windows daemon builds prepare and verify the pinned Computer Use runtime with `python scripts/prepare-computer-use.py` before cargo build. The executable and MIT license are embedded in yi-agentd, so the existing sidecar/SSH deployment flow carries the driver without a runtime download. See [computer-use.md](computer-use.md).
